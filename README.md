# Зублефар — дашборд обращений

Один самодостаточный HTML-файл: **`zublefar-dashboard.html`**. Открывается двойным
щелчком из любой папки, работает **без интернета и без установки**, читает выгрузку
из CRM прямо в браузере и считает усреднённые показатели за предыдущий период
в разрезе тегов **Каталога ОПИК**.

Ни одного внешнего запроса: нет CDN, нет шрифтов с сети, нет аналитики. Файл выгрузки
никуда не отправляется — он разбирается локально в браузере.

## Как пользоваться

1. Скачайте `zublefar-dashboard.html` и положите в любую папку.
2. Откройте файл в браузере (Chrome, Edge, Firefox или Safari актуальной версии).
3. **Каталог ОПИК** → вставьте список тегов каталога (или отберите их из выгрузки).
4. **Загрузить выгрузку** → выберите файл из CRM (или перетащите его на страницу).
5. При необходимости уточните **Колонки** и **Настройки**.
6. **Сохранить** → HTML с настройками, HTML вместе с данными, CSV показателей или печать в PDF.

### Загрузка свежей выгрузки

Поддерживаются `CSV`, `TSV`, `XLSX` и `JSON` (массив объектов).

* Разделитель CSV (`;`, `,`, табуляция, `|`) определяется автоматически.
* Кодировка UTF-8 и Windows-1251 определяются автоматически.
* Даты понимаются в форматах `ДД.ММ.ГГГГ ЧЧ:ММ`, `ГГГГ-ММ-ДД`, `ДД/ММ/ГГГГ`
  и как серийные значения Excel. Порядок дня и месяца переключается в настройках.
* Длительности понимаются как `12:34:56`, `2 д 3 ч 15 мин` или как число
  (единица задаётся в настройках).
* XLSX распаковывается средствами самого браузера — сторонние библиотеки не нужны.

Новая выгрузка **заменяет** предыдущую. Сопоставление колонок и каталог сохраняются:
если заголовки совпадают, настраивать ничего не нужно — достаточно загрузить свежий файл.

### Сопоставление колонок

При первой загрузке колонки определяются автоматически по названиям заголовков.
Обязательны только два поля: **дата создания** и **столбцы с тегами**. Остальные
(дата закрытия, первый ответ, канал, ответственный, оценка, повторные открытия)
включают дополнительные показатели, если такие данные в выгрузке есть.

Теги можно брать сразу из нескольких столбцов — значения объединяются. Внутри ячейки
теги разделяются `;`, `,`, `|` или переводом строки.

### Каталог ОПИК

Аналитика строится **только по тегам Каталога ОПИК**. Значения, которых в каталоге нет,
не попадают ни в один разрез и показываются отдельным счётчиком «теги вне каталога»,
чтобы каталог можно было пополнить осознанно.

Каталог задаётся тремя способами:

* списком в диалоге — одна строка на тег, код отделяется чертой: `ОПИК-04 | Возврат средств`;
* импортом `JSON` (`[{"code":"…","name":"…"}]` или просто массив строк) либо `CSV`;
* отбором из загруженной выгрузки — вкладка «Отобрать из выгрузки» показывает все
  встреченные значения с частотой, отмеченные становятся каталогом.

Каталог сохраняется в браузере и вшивается в файл при сохранении дашборда.

## Что показывает отчёт

Только **предыдущий завершённый период** и только **средние значения**.
Текущий незавершённый период, сравнение с ним и динамика «период к периоду» не выводятся.
**Данные о соблюдении целевого SLA в дашборде отсутствуют** — ни процентов
соблюдения, ни целевых порогов, ни отметок «в срок / просрочено».

| Блок | Содержание |
|---|---|
| Полоса периода | Какой период посчитан и сколько обращений вошло в расчёт |
| Выгрузка | Файл, число строк, охват дат, сколько строк отброшено и почему |
| Средние за период | Обращений в день, время первого ответа, время решения, тегов на обращение, оценка, нагрузка на сотрудника, доля повторных открытий |
| Разрезы | Средний дневной объём и среднее время решения по тегам ОПИК, динамика по дням периода, дневная нагрузка по каналам |
| Каталог ОПИК | Таблица средних по каждому тегу каталога с сортировкой |
| Как считаются показатели | Определения, подстроенные под текущие настройки |

Период выбирается в верхней панели: предыдущий день, неделя, месяц или квартал.
Точка отсчёта — последняя дата в выгрузке (по умолчанию) или сегодняшняя дата.

## Правила расчёта

* **Обращений в день** — число обращений периода, делённое на календарные дни периода
  (переключается на «дни, покрытые выгрузкой»). Если выгрузка закрывает период
  не полностью, дашборд об этом предупреждает.
* **Время решения** — из готового столбца CRM, иначе разница «дата закрытия − дата создания».
* **Время первого ответа** — из готового столбца CRM, иначе «дата первого ответа − дата создания».
* Значения длительности вне диапазона 0–400 дней отбрасываются как ошибочные.
* Рядом со средним приводится **медиана** — распределение времени решения скошено,
  и одно среднее может вводить в заблуждение.
* **Обращения без тегов каталога** по умолчанию исключаются из всех расчётов
  (переключается на «учитывать в общих средних»).
* **Обращение с несколькими тегами** по умолчанию учитывается целиком в каждом своём
  теге — сумма по тегам тогда больше общего числа обращений. Альтернатива в настройках:
  делить объём поровну, тогда сумма долей равна 100 %. Средние времена и оценки
  в обоих режимах считаются по обращениям тега без дробления.

## Сохранение

* **Скачать HTML** — дашборд с каталогом, сопоставлением колонок и настройками внутри,
  без данных. Это версия для раздачи коллегам: открыл и загрузил свою выгрузку.
* **Скачать HTML с данными** — то же плюс загруженная выгрузка. Открывается сразу
  с готовым отчётом, полностью офлайн. Такой файл можно переслать или положить в архив.
* **Скачать CSV** — таблица средних по тегам ОПИК за период, с разделителем `;` и BOM,
  открывается в Excel без настроек импорта.
* **Печать** — раскладка на страницу без панели управления, в том числе в PDF.

## Демо-режим

При первом открытии, пока каталог пуст, дашборд показывает себя на синтетическом наборе
с тегами `DEMO-01 … DEMO-08` и выводит предупреждение. **Это не данные проекта Зублефар
и не Каталог ОПИК** — только иллюстрация работы. При загрузке настоящей выгрузки
демо-каталог автоматически удаляется, чтобы не смешаться с рабочим.

## Требования к браузеру

Chrome/Edge 111+, Firefox 113+, Safari 16.4+. Для XLSX нужен `DecompressionStream`
(есть во всех перечисленных); если браузер старше, выгрузку достаточно сохранить в CSV.

## Что требует уточнения

Дашборд собран как инструмент под данные и правила проекта, но **сама переписка по
проекту Зублефар в этой сессии недоступна** — репозиторий пуст, задач и вложений нет.
Поэтому в файл не зашиты:

* **состав Каталога ОПИК** — коды и названия тегов заполняются в диалоге «Каталог ОПИК»;
* **точные названия колонок выгрузки** — определяются автоматически и правятся в «Колонках»;
* **договорённости проекта о границах периода и об обработке обращений с несколькими
  тегами** — вынесены в «Настройки» с разумными значениями по умолчанию,
  а действующие правила описаны прямо в отчёте, в блоке «Как считаются показатели».

Пришлите выгрузку и Каталог ОПИК — значения по умолчанию можно зафиксировать в файле,
чтобы дашборд открывался сразу с нужными правилами.
