# Статистика решённых задач ОСП

Один автономный файл **`osp-dashboard.html`**: открывается двойным щелчком (file://), работает без сервера и интернета. Пользователь загружает выгрузку задач (.xlsx) и сразу видит статистику по решённым задачам: количество, разбивку по сотрудникам и типам, «Затрачено», время «В работе (а)» и «От создания до закрытия (б)» и их динамику.

- Данные файла остаются в браузере. Сетевые запросы запрещены политикой безопасности страницы (CSP `default-src 'none'`, `connect-src 'none'`).
- Читаются только 9 обязательных колонок. Тексты задач и клиентские реквизиты (описание, ИНН, компания, лид, сделка, CRM, соисполнители) не разбираются, поэтому не попадают ни на экран, ни в экспорт.
- В `localStorage` хранятся только настройки справочников, данные файла — никогда.

## Как пользоваться

1. Откройте `osp-dashboard.html` в Chrome, Edge или Firefox.
2. Перетащите выгрузку в окно или нажмите «Выбрать файл».
3. Слева настраивается показ: сотрудники, типы, период по дате закрытия, постановщик (все / боты / без ботов), режим и шаг динамики, среднее/медиана, исключение выбросов. Всё применяется сразу.
4. Внизу левой панели — «Настройки справочников»: переименование сотрудников и типов, группы типов, скрытие типов, порог «Прочие», список ботов, рабочий календарь, метод выбросов, сопоставление колонок, экспорт/импорт настроек в JSON.
5. «Скачать результаты в Excel» — книга с листами «Параметры», «Сводка», «Сотрудники×Типы», «Показатели», «Динамика», «Выбросы», «Качество данных». У каждого графика и таблицы есть кнопка «PNG»; «Весь отчёт в PNG» сохраняет всю область вывода.

## Разработка

```bash
npm install          # Chart.js 4.5.0, fflate 0.8.2, html2canvas 1.4.1, esbuild
npm run build        # src/ → osp-dashboard.html
npm test             # модульные и сквозные тесты ядра (node:test)
npm run fixtures -- --big   # синтетические xlsx в test/fixtures (в git не попадают)
npm run e2e          # проверка в Chromium (Playwright), скриншоты в docs/screenshots
```

Структура:

| Путь | Назначение |
|---|---|
| `src/core/` | Расчётное ядро без DOM: чтение/запись xlsx, разбор дат, рабочий календарь, типы и «Прочие», выбросы, агрегаты |
| `src/ui/` | Интерфейс: загрузка, панель фильтров, настройки, KPI, графики, таблицы, экспорт |
| `src/styles.css` | Все цвета и шрифты — CSS-переменные в начале файла |
| `test/` | Тесты и генератор синтетической выгрузки той же структуры (39 колонок) |
| `scripts/verify-reference.mjs` | Сверка с эталоном раздела 12 на реальной выгрузке |
| `scripts/e2e.mjs` | Приёмочная проверка в браузере |

### Сверка с эталонной выгрузкой

Реальная выгрузка в репозиторий не попадает (`*.xlsx` в `.gitignore`). Чтобы сверить расчёт с эталонными значениями из задания:

```bash
node scripts/verify-reference.mjs "Выгрузка ОСП 28.10.2026.xlsx"
```

Скрипт использует то же ядро, что и страница, с настройками по умолчанию и печатает по каждой величине «эталон / факт / OK». Счётчики сравниваются точно, длительности — с допуском ±0,001.

Результат на эталонной выгрузке от 28.10.2026: **174 из 174 значений совпали**. Это все величины раздела 12: счётчики, сотрудники × типы, среднее/медиана/n по срезам, помесячная динамика, число выбросов и средние без них, ID 38405. Тот же результат даёт копия выгрузки, где даты и «Затрачено» переведены в нативные типы Excel (через openpyxl). В браузере KPI и выгрузка в Excel показывают те же числа.

## План работ

1. Каркас и сборка в один HTML (esbuild, все библиотеки встроены).
2. Собственный читатель xlsx (fflate + разбор XML): только нужные колонки; даты как «настенное» время, без часовых поясов.
3. Расчётное ядро: рабочие часы, типы, «Прочие», выбросы, агрегаты, периоды. Тесты сравнивают его с независимым наивным расчётом.
4. Интерфейс: загрузка, левая панель, KPI, графики, таблицы, блок настроек.
5. Экспорт в xlsx (собственный генератор: числа числами, ширина колонок, закреплённые заголовки) и в PNG (html2canvas, ×2).
6. Проверка в Chromium по списку приёмки, скриншоты.

## Допущения

- **Аномалии дат.** Если закрытие раньше создания, задача исключается из (а) и (б). Если закрытие раньше начала работы — только из (а). «Затрачено» — записанная длительность, аномалии дат её не затрагивают. В количестве такие задачи учитываются. Этот вариант не противоречит эталону, где у (б) n равно числу решённых задач.
- **«Завершена» без даты закрытия.** Такая задача не решённая и не в очереди. Она учитывается во «Всего задач», отдельно показана в KPI и в блоке качества данных.
- **Порог «Прочие»** считается по всем задачам периметра, включая очередь. Именно поэтому «Произвести регистрацию заявки партнера» с 5 решёнными задачами в эталоне идёт отдельной строкой.
- **«Скрыть» тип** исключает его задачи из всех расчётов, включая пороги выбросов. Число скрытых задач видно в блоке качества данных.
- **Одинаковые отображаемые имена** объединяются: два исходных ФИО, переименованные одинаково, станут одним сотрудником. Для типов то же самое делает поле «Группа».
- **Сотрудники упорядочены по алфавиту** — рейтинга нет. Цвет сотрудника и типа закреплён за ним и не меняется от фильтров.
- **Ось динамики** — от первой до последней даты закрытия в файле (или границ выбранного периода). Пустые периоды на оси есть, линия в них прерывается. Период помечается «неполным», если не закончился к дате среза или обрезан фильтром.
- **Выбросы методом IQR** — только верхняя граница Q3 + k·IQR. Ручной порог задаётся отдельно для каждого показателя.
- **Качество данных:** проверки (нераспознанные значения, дубли ID, аномалии) идут по всему файлу. Заполненность по месяцам считается по текущей выборке решённых задач.
- **Даты в полях периода** вводятся как дд.мм.гггг независимо от языка браузера; есть быстрый выбор месяца.
- **Малая выборка** — n < 5, как в правиле раздела 7. В эталонной таблице так помечен и февраль «В работе (а)» с n = 9, поэтому порог вынесен в настройки справочников («Малая выборка: n <»).
- **Названия задач в экспорте.** В реальной выгрузке у некоторых редких задач в «Названии» стоят ИНН и названия компаний. Поэтому в Excel перечень исходных названий «Прочих» и скрытых типов не выгружается — только их число. В интерфейсе (подсказка к «Прочие», список типов в настройках) названия видны: без них не переименовать и не скрыть тип.
- **Срез** — максимальная дата создания или закрытия в файле. Имена PNG и xlsx строятся по дате среза: `osp_zatracheno_dinamika_2026-10-28.png`.

## Оформление

Цвета взяты из темы шаблона `Шаблон_Группы_Астра_светлый.pptx` (`ppt/theme/theme1.xml`): тёмно-синий текст `#28334E`, акцент `#0077CD`, голубой `#5BC3F5`, фон слайдов `#F4F5F7` и др. Логотип — из шаблона. Шрифт темы — PT Astra Fact. Его файла в шаблоне нет, поэтому он стоит первым в стеке и используется, если установлен в системе; иначе — системный шрифт. Палитра графиков опирается на оттенки шаблона и проверена на различимость при дальтонизме. Линии отличаются ещё и маркером и штрихом, у каждого графика есть таблица данных.
